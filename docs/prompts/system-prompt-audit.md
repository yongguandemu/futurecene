## 二、初始评分依据

### 100-90 分组（直接过）

**P13 游戏操作规划（92）**：完整声明 6 种操作类型 + 参数结构 + JSON 数组示例 + 失败返回 `[]`。结构与鲁棒性俱佳。

### 90-50 分组（模拟输出测试）

**P3 系统能力说明（90）**：6 类真实能力 + 具体示例 + "不要虚构"约束。缺：对非能力类请求的处理指引。

**P4 智能助手中立身份（90）**：明确"不扮演任何虚拟主播角色"，拼接能力说明。缺：回复格式/长度指引。

**P12 记忆压缩摘要（90）**：字数上限 + 保留要素（人物/事件/偏好/时间线）+ 只输出正文。任务边界清晰。

**P5 角色定向说明（88）**：模板 + 能力拼接，明确"保持人设与世界书"。依赖外部 role_prompt 质量。

**P7 工具清单块（88）**：调用格式 `[[TOOL:名:参数]]` + 结果回填说明，格式清晰。

**P11 批量发言策划（88）**：JSON 数组 schema 完整（text/mood/suggested_window_sec/duration_estimate）+ 口语化约束 + 不输出解释。mood 枚举缺示例。

**P6 世界书注入块（85）**：`【世界设定】` + 条目行，token 控制（1500 截断）。缺"如何运用设定"指引。

**P10 主动话题生成（82）**：任务 + 约束（两句话内、无表情符号）+ 上下文注入。无输出格式约束。

**P14 经验学习操作建议（78）**：动作枚举 + 示例（press_key {"vk":32}）。拼装随意，无严格 JSON 声明。

**P8 协作发言权判断（75）**：JSON schema 有（yuki/lilith 紧迫度 0-1 + silent）。缺示例、缺打分依据（什么情况 silent）。

**P15 经验学习失败修正（72）**：有示例（{"x":10,"z":20}）。过于简略，无格式强约束。

**P16 MC 任务拆解（70）**：行格式说明（gather/craft/move_to）。无示例，解析器对格式敏感。

**P9 协作感知彼此（60）**：仅拼接"对方最近发言"，缺利用指引（如何回应/何时忽略）。

**P1/P2 角色人设（55）**：单句设定（性格 + 语气词），缺互动边界、回复长度、背景故事、禁说项。内容单薄，LLM 泛化风险高。
